Good motion. Unconstrained direction.

The library supplies realistic body motion; the runtime chooses a short continuation to follow a root path. Its current score has no explicit preference for forward travel relative to body facing. This report measures what is available and explains how it gets selected.

What motions are actually in the graph?

These are measurements of the saved tables, weighted equally over every valid edge. They describe available motion, not the fraction of time a simulated crowd visits each motion. The original library command labels only distinguish walking and standing.

Exact labeling rules

Velocity comes from successive root positions, including the predecessor frame. Compare it with the midpoint of ARDY root yaw, which encodes body facing. Speed below 0.15 m/s is “still / slow”; moving angles within 30° are forward, 30–60° oblique, 60–120° sideways, and ≥120° backward. Edge labels use the most common frame label (ties favor the earlier class). Forward and slow edges split into “turning” when net body yaw is at least 10° per edge.

These are transparent analysis cutoffs, not empirically established behavior proportions or pass criteria. “Turn in place / slow” is a kinematic label and includes slow translation; it does not prove a deliberate turn animation. Body yaw uses the generator's root representation, not head gaze.

Nodes are library boundaries

Each 32 s stream has 80 boundary nodes, spaced 8 frames apart. A boundary records heading-aligned joint positions and a one-frame finite-difference velocity. The first 0.4 s is startup motion; the last boundary has no natural outgoing clip.

Each valid edge stores the next 8 frames: root displacement, body yaw, joint pose, and contacts. Hunched edges are filtered by mean head height. There are no behavior-tagged hubs or explicit “walk → turn → walk” rules.

Connections are pose-neighbor candidates

For each boundary, find 128 nearest valid edge-start boundaries using joint position and velocity. Score the corresponding outgoing clips online. The actual jump is current boundary b → clip e → boundary e+1, even when e belongs to another stream.

Matching uses a single boundary pose and velocity, not a multi-frame window. Heading is normalized out of the descriptor. Contacts are stored and replayed but are not an explicit candidate filter or score term.

Selection and stitching

cost(e) = root-path RMS error
        + pose_weight × descriptor distance
        + end_vel_weight × end-of-edge velocity error

P(e | current boundary, requested path) ∝ exp(−cost(e) / temperature)

After sampling: rotate/translate onto the current body frame;
bend root yaw by at most ±5° and scale speed by at most ±10%;
decay the start-pose offset over the 8 frames; arrive at node e+1.

Sampling uses independent counter-based Gumbel draws per human. A near-standing valid boundary initializes each person. Pose offset decay smooths joint positions; root velocity is not inertialized. Output is interpolated to the simulator rate.

The current stochastic behavior model

  

   
Offline: broad motion coverage
Each independent stream draws a semi-Markov segment: 20% standing draws (1–4 s) and 80% walking draws (1.5–6 s). Walking speed bands: 15% at 0.3–0.8 m/s, 70% at 0.8–1.5 m/s, 15% at 1.5–2 m/s.
35% of walking draws keep the commanded heading. Otherwise the heading delta is uniform within ±90°, except a 20% chance of using ±180°. Independently, 25% curve with a sampled rate within ±40°/s. These constrain root position; they do not command explicit body facing or deliberately labeled lateral/backward steps.
Segment probabilities are not time occupancy. In the long-duration limit the nominal standing share is about 14.3% before startup and truncation; the measured command share above is from this finite library.

   
Online: random destination walking
Choose a uniformly sampled interior goal and a preferred speed of 0.8–1.6 m/s per goal. Start facing a random direction. Within 0.6 m of a goal, take a 30% wait draw (1.5–4 s) or choose another goal. The new goal may be behind the body.
Every graph boundary, compute goal velocity, neighbor avoidance using closest approach over 3 s (1.2 m personal radius), a hard separation push below 0.9 m, and wall/obstacle repulsion. Avoidance suppresses the goal term. Waiting people can still move to avoid others, up to 0.6 m/s.
The steering RNG is currently shared across all people. Unlike graph sampling and offline generation, these draws depend on call order and batch composition. It remains demo code and does not yet meet the training randomness invariant.

  

  
Why lateral motion can be selected. The current score rewards matching a short world root path while preserving a nearby pose. It does not charge for sustained sideways/backward travel or require a turn before translation. Repulsion and goal changes can request large direction changes. This is a code-supported mechanism; the historical video has no per-person trace, so its precise causal breakdown is not measured.

A small, repeatable iteration loop

  
The report comes first. The tools are prepared; no behavior tuning or new rollout renders have been executed for this report.

  
  1. Freeze inputs. Reuse the saved graph, seed bank and duration. Save resolved steering/scoring settings, the git commit (and diff when dirty) and environment metadata for every run. Keep each candidate in a fresh UTC-stamped directory.
  2. Evaluate without graphics. Use the same plaza steering, path planner and graph runtime to save executed 20 fps motion. Report body-relative forward/side/back proportions, facing error, yaw/path changes, root gaps and planted-foot motion. Load the graph once for all seeds.
  3. Render saved traces. Replay capsule joint motion directly through MuJoCo. Decouple camera, image size and render FPS from behavior evaluation; no prior inference, graph rebuild, Warp compilation or LiDAR pass is required for visual iteration.
  4. Compare matching seeds. Review the exact same people under baseline and candidate settings. Use both the overview and close-up views; keep quantitative tradeoffs visible. Promote promising behavior into an mjlab integration render using the existing demo.
  5. Change one mechanism. First inspect facing/travel misalignment and turning coverage; then tune persistent destinations, forward travel and turn-before-walk selection. Reserve lateral/backward motion for deliberate close-range avoidance. Do not hide a library coverage gap by rotating the body abruptly.

  
The initial seed bank is a reproducibility choice, not a calibration dataset. No numerical “human-like” acceptance criterion is invented. The graph-only harness measures motion/behavior; full mjlab integration and simulator scale need separate validation.
